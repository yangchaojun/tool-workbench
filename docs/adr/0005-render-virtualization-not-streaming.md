# 大文档策略：渲染层虚拟化，拒绝流式/分块解析

"大文件懒加载"被定义为**渲染层的懒渲染**：文档仍一次性完整 `JSON.parse`，数据源模型（ADR-0003）不动；树形视图改为只渲染视口内节点的虚拟滚动，并以此替换 200 子节点渲染上限与"显示全部"补丁；文本视图继续依赖 CodeMirror 6 自带的按行虚拟化。

流式/分块解析被否：部分解析的文档没有完整数据源，树编辑、查询、对比、撤销栈全部要为"半份数据"重新设计，代价数倍而收益仅对超出内存规模的文档成立——那不是本工具的目标场景。

## Consequences

- 上传软上限由 5MB 上调至 20MB；输入 1MB 暂停自动校验、持久化 256KB 两项维持（分别防 `JSON.parse` 卡顿与 localStorage 配额，与渲染无关）。
- 树编辑的全量重序列化在大文档上是 O(n) 成本：实测后设定阈值，超过时树形编辑降级为只读并提示，而非放任卡顿。实测（M 系列芯片，2 空格 `JSON.stringify`）：8MB ≈ 28ms、12MB ≈ 44ms、20MB ≈ 72ms，阈值定为 8MB。
