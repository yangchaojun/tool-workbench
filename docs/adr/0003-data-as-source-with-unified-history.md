# 树形编辑以解析数据为唯一数据源，撤销/重做走应用层统一快照栈

JSON 查看器升级为编辑器后，树形视图可以增删改节点、拖拽排序，文本与树必须共享一份状态。我们决定：**解析后的数据（JSON.parse 的值）是唯一数据源**——树形编辑直接（不可变地）作用于数据，文本视图是它的 `JSON.stringify(…, null, 2)` 序列化投影；文本编辑仍以文本为准，防抖校验合法后写回数据源、树同步刷新。撤销/重做用**应用层统一快照栈**（改动前状态入栈，覆盖文本防抖提交、树操作与一切整段写回动作），并关闭 CodeMirror 内建 history，避免双栈打架。

「文本与树互为数据源、双向绑定」的方案被否：它需要一套双向同步协议来消解「树改了、文本非法」时的冲突窗口，复杂度与出错面都远高于单一数据源。

## Consequences

- 树形编辑必须走**不可变更新**（沿路径浅拷贝父链，见 `editor/mutations.ts`）：快照栈里的旧数据与当前数据共享结构但互不污染，撤销零拷贝成本。
- 文本校验失败期间数据源被标记为**过期（stale）**：树保持只读并提示，恢复合法后自动续接——而不是回滚文本或清空树。
- 连续文本键入按合并窗口收敛为一个历史条目；快照栈上限 100 条、不持久化，刷新即清空。
- 查询、对比、修复的结果同样吃数据源或经 `JSON.parse` 验证（见 ADR-0002），三处不引入第二套解析语义。
- CodeEditor 的契约为此显式扩展：新增 `history` 开关（默认开启，向后兼容），并暴露视图句柄供工具侧实现查找替换。
